# EVRL2026 状态-动作空间详细说明

## 一、状态空间 (State Space)

### 总维度：38维

状态空间是RL智能体观察到的环境信息，用于做出决策。

---

### 1. OD需求特征 (16维)

**维度分配：** 4区域 × 2时间片 × 2类型(流入/流出) = 16维

#### 1.1 OD流入 (od_in) - 8维
- **含义：** 未来2个时间片，每个区域的流入订单需求
- **计算方式：** 从当前时间步开始，观察未来2个时间片的OD需求矩阵
- **取值范围：** 0-5 (离散化，OD_MAX=6)
- **实际意义：**
  - 帮助RL预测未来需求，提前调度车辆
  - 例如：state[0]=3 表示区域0在下一时间片有3个流入订单

**维度映射：**
```
state[0:2]   - 区域0的流入需求 (未来2个时间片)
state[2:4]   - 区域1的流入需求
state[4:6]   - 区域2的流入需求
state[6:8]   - 区域3的流入需求
```

#### 1.2 OD流出 (od_out) - 8维
- **含义：** 未来2个时间片，每个区域的流出订单需求
- **计算方式：** 同od_in，但统计流出方向
- **取值范围：** 0-5
- **实际意义：**
  - 预测哪些区域会有车辆离开
  - 帮助平衡车辆分布

**维度映射：**
```
state[8:10]  - 区域0的流出需求
state[10:12] - 区域1的流出需求
state[12:14] - 区域2的流出需求
state[14:16] - 区域3的流出需求
```

---

### 2. 充电桩占用状态 (8维)

**维度分配：** 4区域 × 2时间片 = 8维

- **含义：** 各区域充电桩的占用率档位
- **计算方式：** `占用率 = available[0][zone] / mem_available[0][zone]`
  - available[0][zone]: 当前区域可用车辆数
  - mem_available[0][zone]: 初始车辆数
- **取值范围：** 0-3 (4个档位，CHARGER_STATES=4)
  - 0: 占用率 0-25%
  - 1: 占用率 25-50%
  - 2: 占用率 50-75%
  - 3: 占用率 75-100%
- **实际意义：**
  - 反映各区域充电桩的繁忙程度
  - 帮助RL决定是否派车去充电

**维度映射：**
```
state[16:18] - 区域0充电桩占用状态
state[18:20] - 区域1充电桩占用状态
state[20:22] - 区域2充电桩占用状态
state[22:24] - 区域3充电桩占用状态
```

---

### 3. 充电桩数量 (8维)

**维度分配：** 4区域 × 2时间片 = 8维

- **含义：** 各区域安装的充电桩数量
- **实际配置：**
  - 区域0: 2个充电桩
  - 区域1: 4个充电桩
  - 区域2: 4个充电桩
  - 区域3: 2个充电桩
  - **总计: 12个充电桩**
- **取值范围：** 0-11 (实际值为2或4)
- **实际意义：**
  - 告诉RL各区域的充电容量
  - 影响充电决策（优先去充电桩多的区域）

**维度映射：**
```
state[24:26] - 区域0充电桩数量
state[26:28] - 区域1充电桩数量
state[28:30] - 区域2充电桩数量
state[30:32] - 区域3充电桩数量
```

---

### 4. 区域平均SOC (4维)

**维度分配：** 4区域 = 4维

- **含义：** 各区域静止车辆的平均电量
- **计算方式：**
  1. 筛选该区域所有静止车辆 (remain==0)
  2. 计算平均SOC
  3. 归一化：`avg_soc / BATTERY_CAPACITY`
  4. 离散化为10档：0-9
- **取值范围：** 0-9
  - 0: 平均SOC 0-10%
  - 5: 平均SOC 50-60%
  - 9: 平均SOC 90-100%
- **实际意义：**
  - 反映各区域车辆的电量健康度
  - 帮助RL决定是否需要充电

**维度映射：**
```
state[32] - 区域0平均SOC
state[33] - 区域1平均SOC
state[34] - 区域2平均SOC
state[35] - 区域3平均SOC
```

---

### 5. 当前时间步 (1维)

- **含义：** 当前处于第几个时间步
- **取值范围：** 0-11 (TIME_NUM=12)
- **实际意义：**
  - 帮助RL学习时序策略
  - 例如：早期时间步可能更注重充电，后期更注重服务

**维度映射：**
```
state[36] - 当前时间步 (0-11)
```

---

### 6. 剩余时间步 (1维)

- **含义：** 距离episode结束还剩多少时间步
- **取值范围：** 0-11
- **实际意义：**
  - 帮助RL规划长期策略
  - 剩余时间少时，可能减少充电，增加服务

**维度映射：**
```
state[37] - 剩余时间步 (0-11)
```

## 二、动作空间 (Action Space)

### 总维度：12维 (连续动作)

动作空间是RL智能体输出的决策，用于控制车辆调度和充电。

**维度分配：** 3类动作 × 4区域 = 12维

---

### 1. 出发倾向 (Departure Preference) - 4维

**维度映射：** action[0:4]

- **含义：** 各区域车辆的出发意愿
- **取值范围：** 0-1 (连续值)
- **实际意义：**
  - 值越大，该区域越多车辆被派出执行订单
  - 例如：action[0]=0.8 表示区域0有80%的车辆倾向出发

**决策过程：**
```python
# 伪代码
for zone in range(4):
    available_cars = get_available_cars(zone)
    dispatch_cars = int(available_cars * action[zone])
    # 派出 dispatch_cars 辆车去执行订单
```

**实际应用：**
- 高需求区域：提高出发倾向，快速响应订单
- 低需求区域：降低出发倾向，保留车辆

---

### 2. 目的地倾向 (Destination Preference) - 4维

**维度映射：** action[4:8]

- **含义：** 车辆前往各区域的倾向
- **取值范围：** 0-1 (连续值)
- **实际意义：**
  - 值越大，越多车辆被调度到该区域
  - 用于主动调度，平衡车辆分布

**决策过程：**
```python
# 伪代码
destination_probs = softmax(action[4:8])
for car in idle_cars:
    destination = sample(destination_probs)
    dispatch_car_to(car, destination)
```

**实际应用：**
- 预测高需求区域：提高目的地倾向，提前调度
- 车辆过剩区域：降低目的地倾向，避免拥堵

---

### 3. 充电倾向 (Charging Preference) - 4维

**维度映射：** action[8:12]

- **含义：** 各区域车辆的充电意愿
- **取值范围：** 0-1 (连续值)
- **实际意义：**
  - 值越大，该区域越多车辆去充电
  - 结合SOC和充电桩可用性做决策

**决策过程：**
```python
# 伪代码（简化）
for zone in range(4):
    for car in get_idle_cars(zone):
        if car.soc < threshold:
            charge_prob = action[8 + zone]
            if random() < charge_prob:
                assign_charger(car, zone)
```

**实际应用：**
- 低SOC区域：提高充电倾向，避免车辆耗尽电量
- 高SOC区域：降低充电倾向，优先服务订单

## 三、状态-动作映射示例

### 示例：时间步0

#### 输入状态 (state)
```python
state = [
    # OD流入 (8维)
    3, 2,  # 区域0: 未来2步有3,2个流入订单
    4, 3,  # 区域1: 未来2步有4,3个流入订单
    2, 1,  # 区域2: 未来2步有2,1个流入订单
    1, 2,  # 区域3: 未来2步有1,2个流入订单

    # OD流出 (8维)
    2, 1,  # 区域0流出
    3, 2,  # 区域1流出
    1, 2,  # 区域2流出
    2, 3,  # 区域3流出

    # 充电桩占用状态 (8维)
    1, 1,  # 区域0: 25-50%占用
    2, 2,  # 区域1: 50-75%占用
    1, 1,  # 区域2: 25-50%占用
    0, 0,  # 区域3: 0-25%占用

    # 充电桩数量 (8维)
    2, 2,  # 区域0: 2个充电桩
    4, 4,  # 区域1: 4个充电桩
    4, 4,  # 区域2: 4个充电桩
    2, 2,  # 区域3: 2个充电桩

    # 区域平均SOC (4维)
    7,  # 区域0: 70-80% SOC
    3,  # 区域1: 30-40% SOC (低电量!)
    8,  # 区域2: 80-90% SOC
    6,  # 区域3: 60-70% SOC

    # 时间步信息 (2维)
    0,   # 当前时间步: 0
    11   # 剩余时间步: 11
]
```

#### RL输出动作 (action)
```python
action = [
    # 出发倾向 (4维)
    0.12,  # 区域0: 12%车辆出发
    0.11,  # 区域1: 11%车辆出发
    0.80,  # 区域2: 80%车辆出发 (高出发率)
    0.22,  # 区域3: 22%车辆出发

    # 目的地倾向 (4维)
    0.35,  # 目的地区域0: 35%倾向
    0.62,  # 目的地区域1: 62%倾向 (高倾向)
    0.93,  # 目的地区域2: 93%倾向 (最高)
    0.29,  # 目的地区域3: 29%倾向

    # 充电倾向 (4维)
    0.97,  # 区域0: 97%充电倾向
    0.96,  # 区域1: 96%充电倾向 (高充电率，因为SOC低)
    0.95,  # 区域2: 95%充电倾向
    0.94   # 区域3: 94%充电倾向
]
```

#### 决策解读

**1. 充电策略：**
- 所有区域充电倾向都很高 (94-97%)
- 特别是区域1 (SOC=30-40%)，需要紧急充电
- **实际结果：** 7辆车在区域1充电

**2. 服务策略：**
- 区域2出发倾向最高 (80%)，因为SOC充足 (80-90%)
- 区域0,1出发倾向低 (11-12%)，优先充电
- **实际结果：** 10个服务订单完成

**3. 调度策略：**
- 目的地倾向：区域2 > 区域1 > 区域0 > 区域3
- 预测区域1,2需求高，提前调度车辆
- **实际结果：** 1辆车从区域3调度到区域2

## 四、关键设计理念

### 1. 时间感知
- 包含当前时间步和剩余时间步
- 帮助RL学习不同阶段的策略
- 例如：早期充电，后期服务

### 2. 未来预测
- 观察未来2个时间片的OD需求
- 支持主动调度，而非被动响应
- 提高服务率和车辆利用率

### 3. 充电信息丰富
- 充电桩占用状态 + 充电桩数量 + 区域平均SOC
- 三重信息帮助RL做出精准充电决策
- 避免充电桩拥堵和电量不足

### 4. 离散化设计
- 所有特征都离散化为整数
- 适合MultiDiscrete空间
- 减少状态空间复杂度，加速学习

### 5. 归一化和缩放
- SOC归一化到0-1，再离散化为0-9
- 动作空间归一化到0-1
- 保证数值稳定性

## 五、当前问题分析

### 问题：RL在时间步1-4不服务订单

**状态观察：**
- 时间步1-4：区域1有大量车辆充电 (8-9辆)
- 充电倾向：action[9] ≈ 0.96-0.97 (非常高)
- 出发倾向：action[0:4] ≈ 0.04-0.08 (非常低)

**原因分析：**
1. **充电奖励过高：** 18,000/车 vs 服务收益 1,500-3,000/单
2. **服务率惩罚过低：** 最大4,000/步 < 充电奖励
3. **RL学到的策略：** 牺牲服务率，最大化充电奖励

**经济学计算：**
```
充电1辆车：+18,000
不服务订单（服务率=0%）：-4,000
净收益：+14,000

结论：充电比服务更赚钱！
```

## 六、改进建议

### 方案1：增大服务率惩罚
- 当前：(0.5 - service_rate) × 8,000，最大4,000
- 建议：(0.5 - service_rate) × 15,000，最大7,500
- 效果：使服务率惩罚接近充电奖励

### 方案2：降低充电奖励
- 当前：18,000/车 (15,000 + 3,000)
- 建议：12,000/车 (10,000 + 2,000)
- 效果：减少充电的吸引力

### 方案3：提高服务率阈值
- 当前：50%服务率开始惩罚
- 建议：70%服务率开始惩罚
- 效果：强制RL服务更多订单

### 方案4：添加服务率奖励
- 新增：service_rate > 0.7 时，奖励 (service_rate - 0.7) × 5,000
- 效果：正向激励，而非仅惩罚

## 七、总结

**状态空间 (38维)：**
- 提供丰富的环境信息
- 支持时序决策和未来预测
- 充电信息完善

**动作空间 (12维)：**
- 连续动作，灵活控制
- 三类动作：出发、目的地、充电
- 支持复杂的调度策略

**当前挑战：**
- 奖励函数不平衡
- RL过度优化充电，忽视服务
- 需要调整奖励参数或重新训练
