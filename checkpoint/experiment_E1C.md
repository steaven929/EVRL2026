## 实验8：方案E1-C - 分段映射优化（无需重新训练）

**实验日期**: 2026.2.7
**实验目标**: 通过改进映射公式，解决充电次数不足的问题（无需重新训练）
**实验类型**: 🔧 映射公式优化（执行层修复）

### 问题诊断

**根本原因分析**（基于深度分析）:
1. **需求分布导致车辆集中**: 车辆主要集中在区域0和区域3
2. **RL学习到错误的区域偏好**: 区域1/2偏好值=1.0，但这两个区域没有车辆
3. **映射公式失效**: `int(pref * idle + 0.5)` 在idle=0时无法充电

**关键发现**（从方案E2增强版的动作文件）:
- 区域1和区域2的充电偏好值=1.0（持续12个时间步）
- 但这两个区域0次充电（因为没有空闲车辆）
- 区域0和区域3的充电偏好值~10^-9，但发生了3次充电

**映射公式的数学缺陷**:
- 当 `idle=0` 时，`int(1.0 * 0 + 0.5) = 0`辆 → 无法充电
- 当 `idle=1` 时，`pref` 需要 ≥0.5 才能充电1辆
- 当 `idle=2` 时，`pref=0.25 → 0辆`，`pref=0.75 → 2辆`（非线性）

### 代码修改

**修改文件**: `specific/dclily_elec.py`

**修改位置**: 第710-729行（check_idle_vehicles函数）

**旧逻辑**:
```python
charge_count = int(pref_value * max_chargeable + 0.5)  # 四舍五入
```

**新逻辑（方案E1-C）**:
```python
# 分段映射策略
if pref_value > 0.8:
    # 高偏好（>0.8）：充电所有空闲车辆
    charge_count = max_chargeable
elif pref_value > 0.5:
    # 中高偏好（0.5-0.8）：充电70%的空闲车辆
    charge_count = max(1, int(max_chargeable * 0.7))
elif pref_value > 0.3:
    # 中等偏好（0.3-0.5）：充电40%的空闲车辆
    charge_count = max(1, int(max_chargeable * 0.4))
elif pref_value > 0.1:
    # 低偏好（0.1-0.3）：充电20%的空闲车辆
    charge_count = int(max_chargeable * 0.2)
else:
    # 极低偏好（<0.1）：不充电
    charge_count = 0
```

### 核心改进

**改进1：提升充电触发概率**
- 旧逻辑：pref=0.5, idle=1 → `int(0.5*1+0.5)=1`辆
- 新逻辑：pref=0.5, idle=1 → `max(1, int(1*0.7))=1`辆
- 效果：中高偏好时，即使只有1辆空闲车辆也会充电

**改进2：高偏好时充电所有车辆**
- 旧逻辑：pref=0.9, idle=5 → `int(0.9*5+0.5)=5`辆
- 新逻辑：pref=0.9, idle=5 → `5`辆（直接充电所有）
- 效果：高偏好时不再受映射公式的舍入误差影响

**改进3：降低低偏好时的充电概率**
- 旧逻辑：pref=0.2, idle=5 → `int(0.2*5+0.5)=1`辆
- 新逻辑：pref=0.2, idle=5 → `int(5*0.2)=1`辆
- 效果：低偏好时仍然可以充电，但数量更少

### 预期效果

**充电次数提升**:
- 方案D2（旧映射）: 5次充电
- 方案E1-C（新映射）: 预期15-30次充电
- 原因: 分段映射提升了充电触发概率，尤其是中高偏好时

**充电分布改善**:
- 旧逻辑: 只有极高偏好（>0.9）才能稳定充电
- 新逻辑: 中等偏好（>0.3）就可以触发充电
- 效果: 更多区域可以参与充电

**无需重新训练**:
- 优点: 立即生效，无需等待训练
- 缺点: 无法改变RL学习到的偏好值分布

### 理论依据

**为什么分段映射更有效**:
1. **降低舍入误差**: 高偏好时直接充电所有车辆，避免舍入损失
2. **提升触发概率**: 中等偏好时也能触发充电，增加充电机会
3. **保持梯度**: 分段映射仍然保持单调性，不影响RL学习
4. **适应车辆分布**: 即使空闲车辆少，也能触发充电
