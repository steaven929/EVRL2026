## 四、根因分析

### 4.1 充电决策逻辑问题

当前充电决策函数 `rl_should_charge()` (dclily_elec.py:446-525):

```python
# 权重配置（2026.2.4修改）
w = {"bias": 0.0, "soc": -1.0, "pref": 5.0, "queue": -1.5, "dist": -0.5}

# 硬阈值（2026.2.4修改）
if soc > 0.8:
    return False  # 强制不充电

# 综合打分
score = w["bias"] + w["soc"]*soc + w["pref"]*pref + w["dist"]*dist_term
p = sigmoid(score)
decision = (random() < p) if training else (p >= 0.5)
```

**问题1: 硬阈值过于严格**
- SOC > 0.8时强制不充电
- 但最优解会在SOC较高时也充电（预防性充电）
- 限制了RL的决策空间

**问题2: 权重配置不合理**
- `soc: -1.0`: 负权重意味着SOC越高越不充电
- `pref: 5.0`: RL偏好权重虽然提高，但仍被SOC和硬阈值压制
- `dist: -0.5`: 距离惩罚进一步抑制充电

**问题3: 决策机制缺陷**
- 训练期使用随机采样 `(random() < p)`
- 推理期使用阈值 `(p >= 0.5)`
- 但由于权重配置，p值很难达到0.5以上

### 4.2 奖励函数问题

从训练曲线看，奖励持续下降，说明：
1. **探索不足**: 智能体没有充分探索充电策略
2. **奖励信号弱**: 充电带来的长期收益没有被正确学习
3. **局部最优**: 陷入"不充电"的局部最优策略

### 4.3 训练过程问题

**负向学习**:
- 前100轮: -4158.60
- 后100轮: -4632.70
- 性能下降11.40%

可能原因:
1. **过拟合**: 学习到了错误的策略模式
2. **探索衰减过快**: Noise衰减导致探索不足
3. **奖励设计缺陷**: 短期惩罚掩盖了长期收益

## 五、优化策略建议

### 5.1 立即可行的改进

#### 方案A: 移除硬阈值
```python
# 删除 dclily_elec.py:478-481
# if soc > 0.8:
#     return False
```
**优点**: 给RL完全的决策自由
**风险**: 可能过度充电

#### 方案B: 调整权重配置
```python
w = {
    "bias": 2.0,      # 增加基础充电倾向
    "soc": -0.3,      # 大幅降低SOC惩罚
    "pref": 10.0,     # 进一步增强RL控制权
    "dist": -0.1      # 降低距离惩罚
}
```
**优点**: 更激进的充电策略
**风险**: 需要重新训练

#### 方案C: 修改决策阈值
```python
# 推理期降低阈值
decision = (p >= 0.3) if not training else (random() < p)
```
**优点**: 更容易触发充电
**风险**: 可能不稳定
