# 基准测试使用指南

## 目的

对比不同策略在当前场景下的性能，找到最优解并与 RL 训练结果对比。

## 测试策略

### 1. 随机策略 (Random Policy)
- **描述**: 完全随机选择动作
- **用途**: 了解最差情况的下界

### 2. 贪心策略 (Greedy Policy)
- **描述**: 根据当前需求分配车辆，不考虑未来
- **逻辑**:
  - 发车倾向：均匀分布
  - 目的地倾向：根据当前 OD 需求
  - 充电倾向：固定值 0.3
- **用途**: 简单启发式策略的基准

### 3. 理论最优策略 (Oracle Policy)
- **描述**: 使用完美信息（假设知道未来需求）
- **当前实现**: 使用固定的"经验最优"分布
- **改进方向**: 可以用动态规划或 MPC 实现真正的最优解
- **用途**: 理论上界参考

### 4. RL 策略 (DDPG Policy)
- **描述**: 当前训练的 DDPG 模型
- **用途**: 评估训练效果

## 对比指标

| 指标 | 说明 | 期望 |
|------|------|------|
| **Episode Reward** | 总体奖励值 | 越高越好 |
| **SVC (服务率)** | 完成订单数 / 总订单数 | 越高越好 |
| **RLD (调度损失)** | 空驶距离 | 越低越好 |
| **SRD** | 服务奖励比 | 越高越好 |
| **AvgSOC** | 平均电量 | 保持在合理范围 |

## 结果分析

### 性能差距分析

**RL vs 随机策略:**
- 如果 RL > Random，说明训练有效
- 差距越大，说明学习效果越好

**RL vs 贪心策略:**
- 如果 RL > Greedy，说明 RL 学到了长期规划
- 如果 RL < Greedy，说明训练不足或奖励函数设计有问题

**RL vs 理论最优:**
- 差距表示还有多少改进空间
- 通常 RL 难以达到理论最优（信息不完美）

### 改进建议

**如果 RL < Greedy:**
1. 检查奖励函数设计
2. 增加训练轮次
3. 调整超参数

**如果 RL 接近 Oracle:**
1. 训练已经很成功
2. 可以尝试更复杂的场景

**如果所有策略都很差:**
1. 检查环境设置
2. 检查奖励函数
3. 可能需要调整问题建模

## 注意事项

1. **测试轮数**: 默认 20 轮，可以根据需要调整
2. **随机种子**: 建议设置固定种子以保证可重复性
3. **环境状态**: 确保所有策略在相同的初始条件下测试
4. **计算时间**: Oracle 策略如果用真正的全局优化会很慢
